## 0. 실행 환경·워크플로 (필독 — 어기면 시간을 태운다)

### 0.1 기본 관례
- **테스트 러너는 `npm test`(= `node --test`)다. vitest가 아니다** — vitest로 돌리면 "No test suite found"가 나오지만 실제로는 테스트가 실행되고 있는 함정이 있다. 헷갈리지 말 것.
- 빌드 체인: `npx vite build` → `npx cap sync android` → `cd android && JAVA_HOME=/d/DEV/android-tools/jdk-21.0.11+10 ./gradlew assembleRelease bundleRelease -q`
  - 빌드 후 `git checkout -- android/app/capacitor.build.gradle android/capacitor.settings.gradle` 로 노이즈 복원. **단, cordova 플러그인을 새로 추가한 경우는 실변경이므로 커밋한다**(v75 전례).
  - `cd android` 후 셸의 cwd가 유지된다 — 다음 명령에서 `android/app/...` 상대 경로가 `android/android/...`가 되는 실수를 반복했다. 확인 명령은 항상 저장소 루트 기준으로.
- PR 관례: `feat/`·`fix/`·`balance/` 브랜치 → 한국어 커밋(본문에 근거·수치·교훈 포함) → `gh pr create` → `gh pr merge --merge --delete-branch`. 매 PR마다 `android/app/build.gradle`의 versionCode +1 (현재 78, 다음 79).
- 폰 설치: `adb devices` 확인 후 `adb install -r android/app/build/outputs/apk/release/app-release.apk`. 미연결이면 "설치 대기"로 보고만.
- E2E: `env -u ELECTRON_RUN_AS_NODE npx electron <스크립트.cjs>` — **ELECTRON_RUN_AS_NODE 해제 필수**(환경에 세팅돼 있어 electron이 순수 node로 떠버림). 스크립트는 `dist/index.html`을 `{ query: { boss: '1' } }` 또는 `{ solo: '1' }`로 로드, `window.__soloNet._sim.state`로 상태 주입/검증, `capturePage`로 스크린샷. 프로필 키는 `localStorage.setItem('bgp.rift.profile.v1', 'tiger')` — **JSON.stringify 금지(raw 문자열)**.

### 0.3 측정 방법론 (밸런스 작업의 헌법)
- **기믹/킷이 완성된 후에만 측정한다**(유저 원칙). 미완성 상태 측정은 무의미.
- 보스전 목표 밴드(봇 5인 기준): **쉬움 35~50 / 악몽 20~35 / 지옥 10~20(중심 15)**. 봇은 학습 상한 프록시 — 사람은 봇보다 잘 깬다.
- 노이즈: **24판 ±10pp, 48판 ±7pp** — 24판으로 방향 잡고 48판으로 확정. 경계 ±2pp는 오차로 수용하고 "실기기 후 재조정" 그룹에 기록.
- **사인 계측 먼저**: 클리어율이 이상하면 "무엇으로 죽는가/왜 못 이기는가"부터. 팀데스가 낮은데 전패면 죽음이 아니라 시간·노동(진군 완료/타임아웃)이 사인이다.
- **파라미터 ±소폭 탐색은 노이즈에 파묻힌다** — 한 레버를 크게 움직여 방향을 확인하고 중간값으로 수렴(이분 탐색). 미세 조정 루프를 3회 이상 돌고 있으면 멈추고 접근을 바꿀 것.

### 0.4 불변 원칙 (설계 헌법 — 위반 금지)
1. **개인 실행 원칙**: 팀이 통계로 풀 수 있는 기믹은 봇 4명이 대신 풀어 사람의 주의가 무의미해진다(야바위 폐기 교훈). 각자 자기 목숨은 자기 실행으로만(시선·도망·회피·배치). "실행하면 산다"가 성립해야 기믹이다 — 확정 사망은 기믹이 아니라 처형 타이머.
2. **피드 문언**: 명령조("~해라!") 금지 + 힌트(공략법·타이머·안전지대 정보) 금지 — 서술형만. 정보 전달은 예고 연출(장판·띠·점멸)의 몫. 결과·상황 서술("N명이 잡혔다")은 힌트가 아니므로 유지. 사망 리캡: 즉사·강타기는 damageHero 6번째 인자 tag(또는 pushBossZone/Line의 `tag`) 한 줄로 "💀 {이름} — {기술}에 스러지다"가 나온다.
3. **경제 원칙**: 보스 전리품은 비매품(토벌의 증표 — 올인원 IAP에서도 제외). 보스전에 증강 금지(디펜스=강해진다, 보스전=능숙해진다 — 축 분리). 세트 효과는 PvE 전용. 광고는 선택형 가산 보상만. 캐릭터는 코인 전용 해금(가격 곡선 UNLOCK_PRICES 300→550).
4. **`hasUnlockAll()`(올인원 IAP) 반영**: 새 잠금/소유 시스템을 만들면 반드시 이 플래그를 소유 판정에 반영할 것(전리품·토벌 조건류만 예외).

### 0.5 코드 함정 목록 (재발 이력 있는 것들)
- **makeView 앨리어싱**: 배열/객체 필드는 반드시 `map()`/`{...}` 복사 — 원본 참조를 넘기면 델타 코덱(lastView)과 공유되어 mid-game 변경이 영영 전송 안 된다(arenaPts→holes→3회 재발).
- **netgame opts 재구성**: 새 게임 opts 필드는 ① netgame 로스터 경로 ② 로컬 어댑터 createGame 나열 — 둘 다 추가해야 전달된다(bossTier·bossRush·arenaRound 전례).
- **모드 전용 봇 두뇌**: 봇 루프 최상단 가로채기로 만들면 아래쪽 공통 안전장치(끼임 구제·botShop·botCombatSkills)가 같이 끊긴다 — 필요한 공통 기능은 직접 호출.
- **스테이지 강제 우회**: 새 모드가 기존 시스템의 스테이지를 강제값으로 우회하면(예: defenseBoss의 stage='march') 그 스테이지의 부수 효과(정예 소환)까지 딸려 온다 — 모든 사이드이펙트 점검.
- **새 위협 메커닉 = 짝 봇 행동 필수**: 봇 대응 없이 넣으면 밴드가 붕괴한다(가시 낙인 17%→산개 봇 추가 42%). 봇이 완벽 회피하면 반대로 기믹이 무력화 — **봇 반응 지연**(0.2~0.45s)이 사람 프록시의 정석 레버.
- **시전 게이트**: 새 스킬/기믹은 콜로세움 준비(shop) 봉인 게이트(castSkill류 상단)와 충돌하지 않는지, 보스전 전용이면 `!h.defenseBoss` 게이트가 있는지 확인.
- **은신+revealT**: 은신 연출 직전 평타의 공격 노출(revealT)이 은신을 뚫는다 — 확실히 사라져야 하면 `h.revealT = 0` 강제.
- **보스 CC 보상**: 보스 CC 저항(3.5배속 소진)이 보상 그로기를 증발시킨다 — 기믹 보상 그로기는 `bossGroggyT`(저항 무시) 사용.
- **저해상도**: 상단 HUD는 폭 ≤720px 다이어트 미디어쿼리 존재 — 새 HUD 요소를 추가하면 640x480에서 확인(E2E `setContentSize` 매트릭스, scratchpad res-matrix-shot.cjs 패턴).
- **씬 시인성**: 암전·어두운 바닥 위 additive 낮은 opacity는 안 보인다 — 경고류는 이중 구조(넓은 띠+밝은 코어)나 밝은 테두리 필수. E2E 캡처로 실화면 확인이 유일한 검증.

### 0.6 권장 실행 순서와 이유
**C → A → D → B.** 방금 결제·경제 구조(IAP 2종, 코인 전용 해금)를 깔았으므로 "살 것"을 채우는 C가 즉효·저위험 1순위. A(신캐)는 최대 코인 싱크이자 볼륨 — C의 상점 인프라 위에 얹는다. D는 중간 규모 심화. B(5번째 보스)는 보스 공정 노하우가 쌓여 있을 때 마지막 대작으로. 각 트랙 안에서도 PR을 작게 쪼갠다(아래 각 트랙의 PR 분할 참조).

## 5. PR별 공통 완료 기준 (DoD)
1. `npm test` 전부 통과(신규 기능엔 신규 테스트 — 총 개수가 늘어야 정상).
2. `npx vite build` 통과. UI 변경 시 E2E 캡처로 실화면 확인(로직 통과 ≠ 보임 — 시인성은 눈으로).
3. 밸런스 영향 있는 변경은 시뮬 수치(전/후)를 커밋 본문에 기록.
4. versionCode +1, 안드로이드 빌드 통과(APK/AAB 생성 확인 — 루트 기준 경로).
5. 커밋 본문에: 무엇을/왜/수치/발견한 함정. Co-Authored-By 트레일러.
6. 큰 결정·교훈은 메모리에 기록(해당 파일에 추가 — 새 파일 남발 금지).
