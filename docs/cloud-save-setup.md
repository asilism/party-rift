# 클라우드 세이브 + 구매 보안 — 콘솔 설정 가이드 (v167)

코드는 전부 들어가 있고, 아래 **콘솔 값 2개**를 채워야 실기기에서 켜진다.
채우기 전까지는 둘 다 조용히 꺼져 있다(게임은 정상 동작).

## 1. Play 게임 서비스 — 클라우드 세이브 활성화

구현: `SavedGamesPlugin.java`(Capacitor 8 앱 내장 플러그인) + `src/shared/cloudSave.js`.
동작: 앱 시작 시 자동 로그인 → 클라우드가 더 새로우면 자동 복원(부팅 지연 상한 2.5초),
앱 이탈 시 자동 저장(15초 스로틀), 설정 화면에 로그인/지금 저장 버튼.

콘솔 절차 (플레이 콘솔 → 성장 → Play 게임 서비스 → 설정 및 관리):

1. **프로젝트 만들기** — "아니요, 게임에서 Google API를 사용하지 않습니다" 경로.
   GCP 프로젝트가 자동 생성/연결된다(기존 OAuth용 GCP 프로젝트 재사용 가능).
2. **저장된 게임 켜기** — 게임 서비스 설정에서 "저장된 게임(Saved Games)" 토글 ON.
   ⚠️ 이걸 안 켜면 스냅샷 API가 조용히 실패한다.
3. **사용자 인증 정보 추가** — Android 유형, 패키지 `com.asilism.zodiacblitz`.
   SHA-1은 **두 개 다** 등록: 업로드 키 + Play 앱 서명 키(콘솔 → 설정 → 앱 무결성에서 확인).
   하나만 넣으면 로컬 빌드나 스토어 빌드 중 한쪽만 로그인된다.
4. **테스터 추가** — 게임 서비스가 "게시 전" 상태인 동안은 등록된 테스터 계정만 로그인 가능.
   본인 계정을 넣고, 출시 시점에 게임 서비스도 **게시**로 전환해야 전체 유저에게 열린다.
5. **프로젝트 ID 복사** → `android/app/src/main/res/values/strings.xml`의
   `game_services_project_id` 값 `"0"`을 숫자 ID로 교체 → 재빌드.

검증: 설정 화면에 "☁️ 클라우드 저장" 행이 나타나면 설정 인식 성공.
로그인 → 지금 저장 → 앱 삭제·재설치(또는 다른 기기) → 첫 부팅에서 코인·해금이 살아 있으면 완료.

## 2. 라이선스 키 — 영수증 서명 검증 활성화

구현: `src/shared/iap.js` `verifyPurchase()` — 구매 영수증의 RSA-SHA1 서명을 Web Crypto로 검증.
위조 앱(Lucky Patcher류)의 가짜 승인 차단. 키가 비어 있으면 검증 생략(현재 상태).

1. 플레이 콘솔 → 수익 창출 설정(Monetization setup) → **라이선스** 섹션의
   Base64 인코딩 공개키 복사.
2. `src/shared/iap.js` 상단 `PLAY_LICENSE_KEY = ''`에 붙여넣기 → 재빌드.

검증: 라이선스 테스터 계정으로 정상 구매가 여전히 지급되는지 확인(정상 구매는 서명이
항상 유효). 위조 도구 테스트는 불필요 — 서명 불일치면 지급을 건너뛰는 코드 경로다.

## 3. 환불 회수 (설정 불필요 — 자동)

`iap.js` `revokeIfRefunded()`: 스토어 초기화가 실제로 성공했는데(가격 로드됨) 상품이
소유 아님이면 로컬 혜택 플래그를 거둔다. 오프라인·조회 실패는 회수하지 않는다(통신 실패 ≠ 환불).
검증: 콘솔 주문 관리에서 테스트 구매 환불 → 앱 재시작 2회(첫 회에 스토어가 소유 해제 전파) →
혜택이 사라지면 정상.

## 남은 한계 (인지된 리스크)

- APK를 직접 패치하는 수준의 공격은 클라 검증으로 못 막는다 — 서버 영수증 검증은
  리더보드 등 서버 기능이 생길 때 함께(피해 범위는 본인 기기 한정).
- 클라우드 세이브는 "최신 승리" 단순 정책 — 두 기기를 동시에 쓰면 나중에 저장한 쪽이 이긴다.
  코인 합산 병합 같은 정교화는 실사용 피드백 후.
